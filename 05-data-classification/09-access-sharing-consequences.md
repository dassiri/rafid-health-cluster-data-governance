# Access and Sharing Consequences

**Document ID:** RHC-DG-P5-009  
**Phase:** 5 — Data classification  
**Status:** Implemented

**Labels used:** `[A]` Fictional assumption · `[B]` Industry best practice · `[C]` NDMO-supported · `[NDMO verification required]`

---

## 1. Purpose

This table states **Rafid working consequences** of each proposed Rafid tier `[A][B]` for access and sharing. It is not an NCA control baseline and not an NDMO specification.

Security consequences stay **high-level**. This file does **not** introduce encryption algorithms, security tools, or cybersecurity architecture. Domain 15 remains under NCA `[C]`; Custodians coordinate with cybersecurity to implement handling.

Phase 4 sharing split remains: business approval vs privacy compliance review.

---

## 2. Approved consequences table `[A][B]`

| Rafid tier `[A][B]` | Internal access (working rule) | External sharing (working rule) | Security consequence (high-level only) |
| --- | --- | --- | --- |
| **Public** | Generally available to the workforce; no special role lock beyond ordinary account standards | May be released externally **only** if the Data Owner has approved a deliberate publication or Public designation | Baseline workplace and platform protections; no extra classification-specific architecture specified here |
| **Internal** | Cluster workforce with a job need; not for the general public | Not for external release by default; Owner business approval required if an external share is proposed | Standard internal handling; Custodian applies agreed internal controls with cybersecurity — **no tools named** |
| **Confidential** | Role-based need-to-know, approved in-policy by the Data Owner (Steward prepares; Custodian provisions) | Owner business approval required; PDPO **C** if personal data is involved | Heightened need-to-know handling; Custodian implements Owner-approved restrictions with cybersecurity — **no algorithms or products named** |
| **Restricted** | Strict need-to-know; in-policy access remains Data Owner **A** | Requires Data Owner business approval + PDPO privacy compliance review where personal data is involved | Strictest Rafid handling band; Custodian implements with cybersecurity / NCA-aligned controls as directed by security — **no algorithms, tools, or architecture specified in this framework** |

The Restricted external-sharing sentence is used **exactly** as approved:

**Requires Data Owner business approval + PDPO privacy compliance review where personal data is involved**

Do not paraphrase that sentence in other Phase 5 files when stating the Restricted external-sharing rule.

---

## 3. What this table does not do

- It does not replace Phase 4 access **exception** (**A = Data Management Committee**).
- It does not reclassify a dataset (sharing ≠ automatic downgrade).
- It does not claim NDMO or NCA compliance.
